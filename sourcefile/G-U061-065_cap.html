G-U061-065_cap：G検定対策サマリー（U061〜U065）

U061〜U065 の評価指標ブロックを、定義・使い分け・ひっかけ・実務への翻訳という観点で圧縮整理する。本文の再要約ではなく、試験で混同しやすい論点を明確にする。

1. この cap の役割

U061〜U065 は、分類モデルの評価指標を一段深く理解するためのブロックである。混同行列の次に来る位置づけとして、単一しきい値での評価 → その統合 → しきい値全体での評価 → 希少陽性への適用 → 確率出力の信頼性 という流れを整理することが重要である。

ここでは本文の再要約ではなく、試験で混同しやすい点と、実務で指標を選ぶときの判断軸を圧縮して整理する。

2. 指標の階層構造

階層代表概念本質
土台混同行列TP, TN, FP, FN の整理
単一しきい値評価Accuracy / Precision / Recall一つの運用点での性能
統合指標F1-scorePrecision と Recall の両立度
しきい値全体評価ROC / AUC / PR 曲線しきい値を動かした全体像
確率の信頼性Calibration予測確率と実頻度の一致

この階層で覚えると、個別指標をばらばらに暗記する必要がなくなる。

3. Accuracy・Precision・Recall の混同防止

  • Accuracy：全体で何件当たったか。クラス不均衡に弱い。
  • Precision：陽性と予測したものの純度。FP を嫌う。
  • Recall：実際の陽性をどれだけ拾えたか。FN を嫌う。

「Precision は見逃しを減らす指標」「Recall は陽性判定の信頼性を見る指標」と逆に覚えないこと。Precision は FP、Recall は FN と強く結び付く。

4. F1-score の位置づけ

F1-score は Precision と Recall の調和平均であり、どちらか一方だけが高い状態を厳しく評価する。しかし TN を直接見ず、コスト構造の重み付けも持ち込まないため、万能ではない。

F1-score は「便利な圧縮指標」だが、最終的な運用判断では Precision と Recall を分解して見る必要がある。

5. ROC と PR の使い分け

状況まず見たいもの理由
モデルの全体的な序列化能力を比較したいROC / AUCしきい値全体でのランキング能力を見やすい
陽性が希少で、誤警報の実害が大きいPR 曲線Precision の低下が直接見える

試験では「不均衡データでは PR 曲線が有効」が定番論点である。ただし ROC を不要とみなすのは行き過ぎである。

6. キャリブレーションの独立性

ROC/AUC が高いことと、確率の値が信用できることは別である。モデルは順位付けは上手でも、自信の度合いを言い過ぎることがある。したがって、確率をそのまま業務判断に使うなら、Calibration を別軸で見る必要がある。

7. 出題されやすいひっかけ

  • Accuracy が高いから性能が高い、と短絡する。
  • Precision と Recall の意味を入れ替える。
  • F1-score を万能指標だと考える。
  • ROC と PR の使い分けを無視する。
  • 高 AUC なら確率も信用できると考える。

8. 実務への翻訳

指標選択とは、何を失敗として重く見るかを明示する作業である。医療・不正検知・故障検知では Recall 重視になりやすく、営業施策・レコメンドの一部では Precision 重視になりやすい。モデル評価は数学だけで完結せず、業務コストとの接続が必要である。

9. このブロックのまとめ

U061〜U065 では、分類モデルの評価を「一つの正解率」から解きほぐし、多面的に見る視点を身につけることが目的であった。G検定では個別指標の定義に加え、どの状況でどの指標を使うべきか を説明できる状態まで持っていくのが理想である。
