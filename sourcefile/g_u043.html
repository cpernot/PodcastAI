G-U043：Embedding ― 言葉や対象をベクトルで表す

Embedding は、単語・画像パッチ・ユーザー・商品など、離散的な対象を連続ベクトルで表す考え方である。現代のAIでは、入力をそのまま扱うのではなく、意味や関係を保った表現へ写してから処理することが多い。ここでは「ベクトルで表すこと」に何の意味があるのかを押さえる。

1. 今回の位置づけ

Attention と Transformer を理解すると、その内部で扱われる「表現」の重要性が見えてくる。Embedding は、その表現の入口にある。

G検定では word2vec や BERT の細かな実装よりも、似た意味のものが近い位置に配置される表現空間 という発想を理解しておくことが重要である。

2. 結論

Embedding とは、単語や対象を低次元の連続ベクトルで表し、意味的・機能的に近いものが近い位置に並ぶように学習された表現である。

この表現によって、モデルは「ただのID」ではなく「関係のある表現」として入力を扱えるようになり、汎化や意味理解の土台ができる。

3. なぜ one-hot では足りないのか

単語を one-hot ベクトルで表すと、語彙数が大きいほど次元が非常に高くなり、しかも「猫」と「犬」が近いといった意味的近さを表現できない。すべての単語が互いに等距離のような扱いになる。

Embedding は、この問題に対して「単語を学習可能な密なベクトルへ変換する」ことで応える。すると、意味や使われ方が似た単語どうしが近い方向や近い位置に配置されやすくなる。

one-hot単純で扱いやすい高次元・類似性を表せない
Embedding密な表現・類似性を表現しやすい学習や事前学習が必要

4. 何を学んでいるのか

Embedding が学ぶのは、単なる記号の圧縮ではない。周囲の文脈や共起関係から、「この単語はどんな役割で使われやすいか」「どの単語と近いか」といった関係をベクトル空間へ写している。

そのため、Embedding は表現学習の一種とみなせる。入力をそのまま処理するのではなく、後段のモデルが扱いやすい形へ変換する前処理兼知識圧縮の役割を持つ。

5. 近いとは何を意味するのか

ベクトル空間で近いということは、意味が完全に同じという意味ではない。むしろ、似た文脈で使われやすい、似た機能を持つ、似た関係性にいる、という近さである。

たとえば「東京」と「大阪」は同じ都市ではないが、都市名として似た位置関係を持ちやすい。Embedding の面白さは、厳密な意味一致ではなく、使われ方や役割の類似が空間構造として現れる点にある。

6. Transformer とどうつながるか

Transformer では、最初にトークンを埋め込みベクトルへ変換してから Self-Attention へ入れる。つまり Embedding は、Attention が扱うための素材を作る入口である。

また、文脈非依存の静的埋め込みと、文脈に応じて変わる文脈化表現を区別する視点も大切である。現代モデルでは、初期埋め込みの上に文脈処理が重なって最終表現が形成される。

Embedding は最終回答そのものではなく、モデルが考えるための「表現空間」を作る工程である。

7. 実務との接点

検索、推薦、クラスタリング、類似文検索、異常検知など、多くの実務で「対象どうしの近さ」を扱いたい。Embedding は、その近さを計算可能にする基盤である。

最近のベクトル検索やRAG（検索拡張生成）でも、文書やクエリをベクトル化して近いものを探す。このため、Embedding の理解は LLM 活用の文脈でも重要性が高い。

8. 試験ポイント

  • Embedding は、離散的な対象を連続ベクトルで表す手法である。
  • one-hot よりも低次元で、類似性を表現しやすい。
  • 近さは意味そのものより、文脈や役割の類似を反映することが多い。
  • 現代モデルやベクトル検索の基礎になる。

9. 人に説明するなら

Embedding とは、単語や対象を、意味や使われ方の近さが反映されるベクトルへ変換する仕組みである。これにより、モデルは記号をそのまま扱うのではなく、関係性を持った表現として処理できる。検索や推薦、LLM の内部表現の理解にもつながる重要概念である。
