G-U071：RLHF・RAG・幻覚

生成AIを実務で使う段階になると、モデル単体の性能だけでは足りない。人の意図に沿った応答へ整える仕組み、外部知識を参照させる仕組み、そしてもっともらしい誤りにどう向き合うかが重要になる。本ユニットでは RLHF・RAG・幻覚を、現代LLM運用の中核論点として整理する。

このユニットの要点
  • RLHF は人間の好みに沿う応答へモデルを寄せる調整枠組みである。
  • RAG は外部知識を検索・参照してから生成する構成であり、基盤モデル単体の知識限界を補う。
  • 幻覚は流暢さと正確さのズレから生じる代表的失敗であり、システム設計全体で対処する必要がある。

1. 今回の位置づけ

前ユニットでは、生成AI・基盤モデル・Instruction Tuning を整理した。今回はその続きとして、「高性能な基盤モデルを、どう業務で使える形へ近づけるか」を扱う。モデルが大きくても、それだけで正しく、根拠付きで、意図どおりに答えられるわけではない。そのギャップを埋める代表的な発想が RLHF と RAG であり、そこから見えてくる失敗形が幻覚である。

2. 結論

RLHF は 人が好ましいと感じる応答へモデルを寄せる調整、RAG は 外部知識を検索して参照しながら生成する構成、幻覚は もっともらしいが誤った内容を生成する現象 と整理できる。3つは別概念だが、実務では密接に結び付き、生成AIシステムの品質を大きく左右する。

重要：基盤モデル単体の賢さと、業務で安心して使えるシステムであることは同じではない。RLHF や RAG は、その差を埋めるための実務上の工夫である。

3. RLHFとは何か

RLHF は Reinforcement Learning from Human Feedback の略である。人間が複数の応答候補を比較し、どちらがより望ましいかを与えることで、モデルを人間の期待に沿う方向へ調整する枠組みである。

ここでいう「望ましい」とは、単に正解であることだけではない。無礼でない、危険助長しない、冗長すぎない、指示に従う、といった対話品質も含まれる。つまり RLHF は、知識そのものを増やすよりも、応答のふるまいを人間中心に整える役割が強い。

観点Instruction TuningRLHF
目的指示に従いやすくする人にとってより望ましい応答へ寄せる
主なデータ指示と模範応答人間による好み比較や評価
直感答え方の型を教える答え方の質感を磨く

G検定では、Instruction Tuning と RLHF を混同しないことが重要である。前者は教師あり調整、後者は人間フィードバックにもとづく追加最適化として整理すると理解しやすい。

4. RAGとは何か

RAG は Retrieval-Augmented Generation の略である。ユーザの質問に対して、まず関連文書を検索し、その結果を参照しながら回答生成する構成を指す。つまり、モデル内部の重みだけで答えるのでなく、外部知識を取りに行ってから生成するのが特徴である。

RAG が重要なのは、LLM が学習時点以降の情報に弱いこと、企業内文書や最新マニュアルのような学習済みでない情報を使いたいこと、回答根拠を文書へ結び付けたいことにある。

典型的な流れ：
ユーザ質問 → 質問をベクトル化 → 類似文書検索 → 関連文書を文脈へ追加 → 回答生成

ここでは Embedding とベクトル検索が重要になる。RAG は強力だが、検索対象や検索品質が悪ければ生成品質も上がらない。

5. 幻覚（Hallucination）

幻覚とは、生成AI が もっともらしいが誤った内容 を出す現象である。存在しない論文を挙げる、誤った仕様を断定する、文脈にない事実を補ってしまう、などが典型例である。

背景には、LLM が本質的に「次にもっとも自然らしいトークン」を予測する仕組みであることがある。これは文章の流暢さには強いが、真偽照合を内蔵しているわけではない。そのため、知らないことに対しても、自然な文章を返してしまうことがある。

注意：流暢で自信ありげな出力ほど危険な場合がある。生成AIの品質確認では、文体よりも根拠と検証可能性が重要である。

6. 3者の関係

RLHF は応答の望ましさを改善し、RAG は知識アクセスを強化し、幻覚はそれでも残りうる失敗現象である。したがって、「RLHF を入れたから幻覚がなくなる」「RAG を入れたから完全に正しくなる」と考えるのは誤りである。

  • RLHF：答え方の振る舞い改善
  • RAG：知識アクセスの強化
  • 幻覚対策：検索品質改善、根拠提示、プロンプト設計、ヒューマンレビューなどの総合対応

7. 実務での論点

業務で生成AIを使う場合、重要なのは単発精度よりも、誤答時にどう扱うかである。FAQ なら人手エスカレーション、文書要約なら原文リンク表示、社内検索なら引用箇所提示、といった設計が必要になる。

また、RAG を使っても参照文書が古い、権限管理が不適切、断片文書の切り方が悪い、検索対象が狭いと性能は落ちる。したがって RAG は単なる機能でなく、知識基盤設計と見るべきである。

8. 試験ポイント

  • RLHF は人間フィードバックを用いた応答調整である。
  • RAG は外部知識を検索・参照しながら生成する構成である。
  • 幻覚は流暢さと正確さのズレから生じる代表的問題である。
  • Instruction Tuning と RLHF を混同しない。

9. 次回への橋渡し

生成AIを実運用するには、性能だけでなく社会実装上のルールが要る。次は、公平性・説明可能性・著作権・責任分界を含む AI倫理・法務・ガバナンス を整理する。
